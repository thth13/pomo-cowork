# Пять редакционных статей для /blog

Дата добавления: 2026-10-22. Раздел `/blog` согласован с владельцем: `/journal`
содержит личные записи и закрыт от индексации. Статьи написаны на английском,
как существующие публичные материалы, и имеют `published: true` для следующего
деплоя. Публикация на сервере в рамках задачи не выполнялась.

## Темы и поисковые задачи

| URL после /blog/ | Основная задача читателя | Самостоятельная польза |
| --- | --- | --- |
| `how-to-run-online-coworking-session` | Организовать online coworking session | Часовая повестка, приглашение, правила опоздания и check-in |
| `pomodoro-25-5-vs-50-10` | Сравнить 25/5 и 50/10 | Расчёты времени с перерывами и критерии выбора интервала |
| `how-to-make-weekly-study-plan` | Составить weekly study plan | Пример пяти учебных дней с резервом и восстановлением после пропуска |
| `timeboxing-for-busy-days` | Применить timeboxing к конкретной задаче | Пример inbox triage, правило остановки и шаблон |
| `weekly-project-review` | Провести weekly project review | Обзор на 15 минут, заполненный пример и выбор следующего действия |

Статьи раскрывают практические вопросы, а страницы Tools предоставляют инструменты.
Новые материалы не повторяют два существующих общих текста о Pomodoro. Примеры
служат иллюстрациями: вымышленных отзывов, личного опыта автора или результатов
клиентов нет. Автор указан как организация Pomo Cowork. Тексты не обещают
синхронный запуск таймеров, автоматическое бронирование, облачное хранение учебного
плана или измерение качества работы по времени сессии.

## SEO и источники

Отдельные title и description описывают содержание каждой статьи. Первый H1
формирует существующий шаблон; Markdown начинается с вводного текста и H2.
Контекстные ссылки ведут к инструментам и другим статьям. Объём определялся тем,
сколько нужно для объяснения сценария, без цели повторять ключевую фразу заданное
число раз. Такой подход согласуется с [рекомендациями Google по полезному контенту](https://developers.google.com/search/docs/fundamentals/creating-helpful-content).

Заголовки проверены на ясность и различимость по [рекомендациям для title](https://developers.google.com/search/docs/appearance/title-link),
описания — на соответствие статье по [рекомендациям для сниппетов](https://developers.google.com/search/docs/appearance/snippet).
Длина строки сама по себе не гарантирует отображение без обрезки или выбор этого
текста поисковой системой.

Учебная статья ссылается на [обзор UC San Diego о распределённой практике и воспроизведении по памяти](https://psychology.ucsd.edu/undergraduate-program/undergraduate-resources/academic-writing-resources/effective-studying/index.html).
Это основание для краткого объяснения подходов, а не подтверждение конкретного
пятидневного расписания. Остальные материалы предлагают практические сценарии
без утверждений о доказанном приросте продуктивности.

его существующими `remark` / `remark-html` с очисткой HTML. Приложение не запускалось.

- Все пять файлов имеют корректные front matter, даты, язык и атрибуцию.
- Title и description уникальны среди всех опубликованных статей проекта.
- Нет второго H1, пропущенных уровней заголовков или повторяющихся длинных абзацев между новыми текстами.
- Все 20 внутренних ссылок имеют существующий маршрут или опубликованную статью.
- Markdown успешно преобразуется в очищенный HTML.
- По исходникам проверено подключение опубликованных файлов к списку `/blog`,
  `generateStaticParams`, canonical, Open Graph, Twitter, BlogPosting,
  BreadcrumbList и sitemap. Отдельные маршруты и записи sitemap вручную не нужны.
- `/blog` не входит в запрещённые пути `app/robots.ts`.
- `git diff --check` прошёл для отслеживаемых изменений в рабочем дереве.

Это статическая редакционная и техническая проверка, а не отчёт Lighthouse,
внешнего сервиса уникальности или AI-детектора. Сборки, сервер и `tsc` не запускались.
После деплоя остаётся открыть пять URL, посмотреть исходный HTML и `/sitemap.xml`,
проверить читаемость на телефоне и фактическую индексацию в Search Console.
